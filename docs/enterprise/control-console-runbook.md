# Enterprise Control API and console

The Spring Boot API under `java/enterprise-control-api` exposes governed tenant, organization, project, integration, quota, cost and API-key lifecycle operations. Each write recomputes a canonical action digest that binds operation, resource, tenant, requester, approvals, timestamp, reason and governed payload before it calls PEP; it then reserves a request digest under the idempotency key, mutates tenant-scoped state, writes the audit result and completes the idempotency record in one database transaction. API-key material is generated with `SecureRandom`, stored only as HMAC-SHA-256 and returned once with `Cache-Control: no-store`; a retry never stores or replays the secret.

The BFF aggregates authoritative service ports with bounded connection/read timeouts; it never joins service databases or manufactures a complete response when a dependency fails. Every query is tenant scoped and bounded. Admin actions require an OAuth2 JWT subject, tenant/project scope, RBAC/ABAC, secure double-submit CSRF and separated approval.

Production startup requires HTTPS PEP and authority endpoints plus these environment variables: `AGENT_TRUST_DATABASE_URL`, `AGENT_TRUST_DATABASE_USER`, `AGENT_TRUST_DATABASE_PASSWORD`, `AGENT_TRUST_IAM_ISSUER`, `AGENT_TRUST_CONSOLE_ORIGINS`, `AGENT_TRUST_SERVICE_TOKEN`, `AGENT_TRUST_API_KEY_PEPPER`, `AGENT_TRUST_PEP_ENDPOINT` and each configured authority endpoint. The database account must be `NOSUPERUSER NOBYPASSRLS` and its connection must use TLS; startup rejects either violation. Migration `0036_02_global_tenant_isolation.sql` enables and forces row-level security on every public table that owns a `tenant_id` column; the PostgreSQL integration gate rejects any later tenant table missing either flag. Each transaction sets `app.tenant_id` locally before access.

The Vue console displays unavailable sections explicitly, never dumps section payloads, and sends intents only. It uses the authoritative policy digest instead of a placeholder and computes the canonical action binding with Web Crypto. Production builds fail when the configured Control API is missing, non-HTTPS or contains credentials, and public source maps are disabled. Task completion is shown only when runtime state, ledger, evaluator, and evidence all agree. Signed webhooks are replay protected in the shared Rust enterprise service.

Before production, connect enterprise IAM, provision tenant/organization/project ownership, run authenticated browser E2E including cross-tenant, IDOR, CSRF/XSS and sensitive-export negatives, exercise partial BFF failure, and validate live IAM/notification/ticketing/SIEM/Webhook adapters. These external gates remain `NOT_RUN`.
